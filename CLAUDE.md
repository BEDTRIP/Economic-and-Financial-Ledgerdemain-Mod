# E&F: Ledgerdemain — правила для агента (загружается автоматически)

Мод Victoria 3 1.13: форк E&F 4.1.7 (автор EBTX) со встроенным PSC 1.3.7 и перенесённым хотфиксом проекта. Соседний репо
`../vic3_mods` — инструменты (`tools/`, мост `vic3-pc`), навыки (`night-run`, `night-until`, `vic3-sandbox`), общие
правила git и движка (`Правила работы с модами Victoria 3.md`).

## Что читать

| вопрос | где | когда |
| --- | --- | --- |
| что сейчас; как идёт и закрывается этап | `план.md` | **всегда, первым** |
| всё по этапу: цель, решения до кода, очередь, перенесённое, аудит, проверки закрытия | `этапы/<этап>.md` | работа над этапом |
| что это и зачем — понятия мода | `понятия/`, вход — `_Карта понятий.md` | перед правкой подсистемы — её понятия |
| как это в игре — понятия игры | `ваниль/`, вход — `_Карта ванили.md` | механика мода стоит на механике игры |
| почему так | `решения.md` | выбор не очевиден |
| где в коде | `docs/README.md` → документ подсистемы | перед правкой кода |
| как было | `история/` | только по ссылке из плана, этапа или решения |
| мёртвый код | `_archive/README.md` | возвращаешь или выносишь механизм |

Obsidian открывает корень форка как хранилище: ссылки — `[[Имя заметки]]`. Игра читает только `common/`, `gui/`,
`events/`, `localization/`, `gfx/` и т. п.; документация в живую копию не попадает (`ld_sync_live.py`).

## Понятия

- Заметка понятия мода — две части. **`## Подсказка`** — текст будущей подсказки-понятия в игре, как ванильные
  (`ваниль/`): для игрока, на «вы», целевое поведение, без кода, номеров решений, этапов и слов «мод» / «движок»; каждый
  термин, у которого есть заметка (мода или игры), — ссылка `[[Имя|форма]]` при первом упоминании в абзаце.
  **`## Рабочее`** → `### Целевое значение` (свойства, правила, решения `Д.…`, открытое, «E&F, не решалось») и
  `### Что в коде` (сделано / частично / нет и этап, переменные, `docs/…`). Тег `устройство` — подсказка в игру не
  идёт; тег `обзор` — свободный формат.
- **Термин игры заметкой мода не заводится.** Как форк его использует — раздел «### Как используется в форке» его
  ванильной заметки (при нужде `#### Целевое значение`, `#### Что в коде`). Своя заметка — только у понятия, которого в
  игре нет. Текст игры в `ваниль/` — генерат (`../vic3_mods/tools/regen_ld_vanilla_concepts.py`, с ПК или мостом),
  руками не править (после обновления игры — перегенерировать); раздел форка генератор сохраняет. Утверждение о механике
  игры — по тексту подсказки или файлам игры, не по памяти.
- Новое понятие — заметка и строка в `_Карта понятий.md`; на каждую заметку кто-то ссылается. Правка поведения понятия —
  правка его заметки в том же коммите, что код и `docs/`.
- Перед правкой подсистемы — её понятия, сверить с кодом: расхождение — не «так в коде», а исправление по решению или
  вопрос пользователю. Унаследованное от E&F без решения — пометка «E&F, не решалось» (кандидат в вопрос).
- **Новых ручек не изобретать** ([[Принципы мода]], п. 14; Д.П.1): сначала найти механику игры или мода, которая явление
  уже изображает (коррупция — нехватка бюрократии, недоверие — радикалы, маргинальность — статус терпимости); новое — с
  объяснением, что искал и почему не подошло.
- Перенос строк заметок — `ld_md_wrap.py` (вики-ссылки не рвёт); формат и ссылки — `ld_docs_check.py`.

## Решения, docs, план, история

- `решения.md` — строка на решение в действующем виде; новое, меняющее старое, переписывает его строку («заменено Д.N»);
  номер `Д.<этап>.<n>` уникален; код и документы ссылаются на номер. Подробно — шапка реестра.
- `docs/` — документ начинается со смысла (что это в игре), ссылок на понятия и решения, пометки «от E&F, не решалось»;
  дальше — файлы, переменные, вызовы, порядок, логи. Всегда актуален: правка кода, меняющая описанное, — правка
  документа в том же коммите. Без истории.
- `план.md` и `этапы/` держат только открытое; закрытое — `история/ГГГГ-ММ-ДД тема.md` (в имени без `:` и `*?"<>|` —
  Windows не возьмёт файл) и строка в `история/README.md`. Как закрывается этап — `план.md`, «Как идёт этап».

## Файлы и код

- Файлы E&F и PSC — под своими именами; правка — прямо в теле определения, не накладкой поверх.
- Новые файлы — префикс `ld_`. Исключение — файл, который обязан подменить ванильный по пути (`gui/companies_panel.gui`,
  `gui/construction_panel.gui`).
- GUI-тип регистрирует **первый** файл по имени (ASCII, по всем модам; при равных — ближе к корню `gui/`); дубль типа —
  мёртвый код, его удалять.
- Локализация: русская и английская полные; девять языков — копия английской: после правки английской —
  `ld_loc_langs.py`.
- `ld_port_hotfix.py` (перенос хотфикса) после ручных правок **не запускать** — пересоберёт файлы E&F из оригиналов.
- **Комментарии в коде — только актуальное** (пользователь 8.10): что делает блок и почему так сейчас; факты движка из
  проб; номер решения, если выбор не очевиден. Без истории — дат, прогонов, «было / was», старых чисел и имён: она в git
  и `история/`. Правишь блок — убери историю из его комментария; в генерате — в генераторе. Правишь файл — снимай в нём
  дубли, новые числа — сразу именованными.
- Мёртвый механизм не удаляется, а переносится в `_archive/` по правилам `_archive/README.md`.

## git и проверка

- Только `master` (здесь) и `main` (`vic3_mods`); ветки `claude/*` облачной сессии не использовать: в начале —
  `git checkout master && git pull`, мост — `checkout_fork("master")`. Остальные правила git — `../vic3_mods/CLAUDE.md`.
- Коммит после каждой законченной задачи и сразу `git push`; пути — явно (`git add -- <пути>`); сообщение по-русски
  `<шаг>: <что сделано>`, в теле — что было, как выглядело в игре, почему так.
- Перед коммитом кода (инструменты — `../vic3_mods/tools/`): `ld_braces.py`, `ld_index.py`, `ld_docs_check.py`,
  генераторы с `--check`.
- Живая копия `mod/E&F Ledgerdemain` — `ld_sync_live.py` (не во время игры). Прогон — навык `vic3-sandbox`,
  `-Playset "Ledgerdemain"`.
