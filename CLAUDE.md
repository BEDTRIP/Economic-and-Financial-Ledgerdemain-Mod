# E&F: Ledgerdemain — правила для агента (загружается автоматически)

Мод Victoria 3 1.13: форк E&F 4.1.7 (автор EBTX) со встроенным PSC 1.3.7 и перенесённым хотфиксом проекта. Инструменты форка (анализы
прогонов и сейвов, генераторы `ld_*`) — `tools/` этого репо; общие — команды `v3` и мост `vic3-pc` репо `../vic3_tools`;
соседний `../vic3_mods` — пачка (компачи, мегапаки, аддоны, выкладки; её план — `План проекта.md`) и навыки
(`night-run`, `night-until`, `vic3-sandbox`). Движок и
компачи — навыки `vic3-modding` и `vic3-compat` плагина vic3tools (`../vic3_tools/claude-plugin/skills/`).

## Понятия

- Заметка понятия мода — две части. **`## Подсказка`** — текст будущей подсказки-понятия в игре, как ванильные
  (граф ваниль): для игрока, на «вы», целевое поведение, без кода, номеров решений, этапов и слов «мод» / «движок»; каждый
  термин, у которого есть заметка (мода или игры), — ссылка `[[Имя|форма]]` при первом упоминании в абзаце; абзац —
  одной строкой, как текст подсказки в игре.
  **`## Рабочее`** → `### Целевое значение` (свойства, правила, решения `Д.…`, открытое, «E&F, не решалось») и
  `### Что в коде` (сделано / частично / нет и этап, переменные, `docs/код/…`). Тег `устройство` — подсказка в игру не
  идёт; тег `обзор` — свободный формат.
- **Граф ваниль описывает только игру** (решение узла Д.ДОК.15). Как форк пользуется понятием игры — заметка форка
  «<понятие> в форке» (`tags: [использование]`, `uses: ["[[<понятие игры>]]"]`, раздел «## Рабочее»), в карте — группа
  «Понятия игры в форке»; в заметку ваниль форк не пишет. Понятие, которого в игре нет, — обычная заметка мода. Термины
  игры — генерат `tools/regen_ld_vanilla_concepts.py` из снимка 1.13 в `../vic3_mods_out/.vanillaVIC3` в
  `../vic3_mods_out/docs/vanilla/Термины/`, руками не править (ручной раздел — «## Рабочее», генератор его сохраняет).
  Утверждение о механике игры — по тексту подсказки или файлам игры, не по памяти.
- Новое понятие — заметка и строка в `_Карта понятий.md`; на каждую заметку кто-то ссылается. Правка поведения понятия —
  правка его заметки в том же коммите, что код и `docs/код/`.
- Перед правкой подсистемы — её понятия, сверить с кодом: расхождение — не «так в коде», а исправление по решению или
  вопрос пользователю. Унаследованное от E&F без решения — пометка «E&F, не решалось» (кандидат в вопрос).
- **Новых ручек не изобретать** ([[Принципы мода]], п. 14; Д.П.1): сначала найти механику игры или мода, которая явление
  уже изображает (коррупция — нехватка бюрократии, недоверие — радикалы, маргинальность — статус терпимости); новое — с
  объяснением, что искал и почему не подошло.
- Перенос строк заметок — `ld_md_wrap.py` (вики-ссылки не рвёт, абзацы подсказки склеивает); формат и ссылки —
  `ld_docs_check.py`.

## Решения, docs, план, история

- `docs/решения/Д.<этап>.<n> — <тема>.md` — файл на решение по методике узла («Решение»): «Решили», «Последствия»,
  «Отвергнуто»; `status` `open` / `active` / `replaced`. Новое, меняющее старое, переписывает его «Решили»;
  отменённое целиком — `replaced` с `replaced_by` и в `docs/история/решения/`. Номер уникален и постоянен; код и
  документы ссылаются на номер. Реестр одной таблицей до 29.10 — снимок `docs/история/Реестр решений до этапа ДОК.md`.
- `docs/код/` — документ подсистемы начинается со смысла (что это в игре), ссылок на понятия и решения, пометки «от E&F, не решалось»;
  дальше — файлы, переменные, вызовы, порядок, логи. Всегда актуален: правка кода, меняющая описанное, — правка
  документа в том же коммите. Без истории.
- `план.md` и `этапы/` держат только открытое; закрытое — `docs/история/ГГГГ-ММ-ДД тема.md` (в имени без `:` и `*?"<>|` —
  Windows не возьмёт файл) и строка в `docs/история/README.md`. Как закрывается этап — `план.md`, «Как идёт этап».

## Файлы и код

- Файлы E&F и PSC — под своими именами; правка — прямо в теле определения, не накладкой поверх.
- Новые файлы — префикс `ld_`. Исключение — файл, который обязан подменить ванильный по пути (`gui/companies_panel.gui`,
  `gui/construction_panel.gui`).
- GUI-тип регистрирует **первый** файл по имени (ASCII, по всем модам; при равных — ближе к корню `gui/`); дубль типа —
  мёртвый код, его удалять.
- Локализация: русская и английская полные; девять языков — копия английской: после правки английской —
  `ld_loc_langs.py`.
- `ld_port_hotfix.py` (перенос хотфикса) после ручных правок **не запускать** — пересоберёт файлы E&F из оригиналов.
- **Комментарии в коде — только актуальное** (пользователь 8.10): что делает блок и почему так сейчас; факты движка из
  проб; номер решения, если выбор не очевиден. Без истории — дат, прогонов, «было / was», старых чисел и имён: она в git
  и `docs/история/`. Правишь блок — убери историю из его комментария; в генерате — в генераторе. Правишь файл — снимай в нём
  дубли, новые числа — сразу именованными.
- Мёртвый механизм не удаляется, а переносится в `_archive/` по правилам `_archive/README.md`.

## git и проверка

- Только `master` (здесь) и `main` (`vic3_mods`); ветки `claude/*` облачной сессии не использовать: в начале —
  `git checkout master && git pull`, мост — `checkout_fork("master")`. Остальные правила git — `../vic3_mods/CLAUDE.md`.
- Коммит после каждой законченной задачи и сразу `git push`; пути — явно (`git add -- <пути>`); сообщение по-русски
  `<шаг>: <что сделано>`, в теле — что было, как выглядело в игре, почему так.
- Перед коммитом кода (инструменты — `tools/`): `v3 lint` (скобки и проверки tiger; известное — `v3-lint.toml`: шум с причиной, настоящее — `plan = "R12 Л.N"`;
  новый отчёт — разобрать в одно из двух, а не в базу; `v3 lint --triage` — все группы),
  `ld_index.py`, `ld_docs_check.py`, генераторы с `--check`.
- Живая копия `mod/E&F Ledgerdemain` — `ld_sync_live.py` (не во время игры). Прогон — навык `vic3-sandbox`,
  `-Playset "Ledgerdemain"`.
