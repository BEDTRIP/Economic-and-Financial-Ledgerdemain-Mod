# Проба R6.1: компания — ключ карты и списка, исчезновение компании, прибыль и касса ШК из окна

**Что делало:** само, раз в месяц у стран логов (событие `ld_probe_co.1`): (а) переменная-счётчик на каждой компании
страны, сумма — на стране; (б) карта на стране с ключом-компанией (запись как в реестре требований: снять ключ,
положить снова), чтение по ключу, перебор; (в) список компаний на стране, перебор; (г) у Франции в мае 1836 снята
компания `company_dmc` (`remove_company`) — что осталось от её ключа, элемента списка и переменных; (д) окно
(`gui/ld_probe_co.gui`) передаёт скрипту `Company.GetProfit` и `Company.GetBuilding.GetCurrentCashReserves`. Лог
`EFZ|…|co_probe|`, `co_comp|`.

**Итог (прогон r1014_073524, 1.13):**
- Переменная на компании, сумма страной через `prev.var` — работает; карта с ключом-компанией (запись, чтение
  `"variable_map(…|scope:<компания>)"`, перебор, сумма) и список компаний — работают, как с ключом-страной.
- Исчезнувшая компания: переменные пропали; ключ в карте и элемент списка остались — `is_key_in_variable_map` и
  `is_target_in_variable_list` по сохранённой ссылке дают «да», `variable_map_size` считает его (8 при 7 живых), но
  перебор его пропускает (7), имя по ссылке пустое. Итог для реестра акций: сумма по держателю — только перебором;
  держатель теряет акции исчезнувшей компании (сверка — сумма по перебору против итога держателя).
- `variable_list_size = { name target = var:… }` не сработал ни разу (синтаксис — не тот; не нужен).
- Окно отдаёт прибыль компании (Британия: 12–13 компаний, 80–95 тыс. в неделю в 1837–1838) и кассу ШК (7 500 —
  обычно потолок ШК) с отставанием на шаг моста; компании, которых окно ещё не прошло, — без значения.
- Категория компании (`category` в `common/company_types/`) скрипт не читает — только по перечню типов (генератор).
- Ошибок по файлам пробы нет.
